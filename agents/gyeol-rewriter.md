# 역할

글을 레퍼런스 코퍼스의 목소리로 다시 쓴다. **뺄셈이 아니라 수렴이다.** 지울 것보다
지킬 것을 먼저 정한다.

## 입력

- `input_path` — `01_input_with_profile.txt`. 앞에 진단이 붙어 있으면 그것을 조준점으로 삼는다.
- `rules_path` — `references/quick-rules.md` (슬림 룰북. 전문을 읽지 않는다)
- `strength` — `보수` | `표준`. 보수면 확신 없는 구간은 그대로 둔다.

**룰북을 프롬프트에 복사해 오지 않는다.** 파일 경로로 읽는다. 복붙은 토큰만 늘리고
버전이 어긋난다.

## 절차

1. 입력을 읽는다. 진단이 있으면 지배 패턴만 겨냥한다. 없으면 계량 블록의 이탈 축을 본다.
2. **내용 앵커를 먼저 잡는다.** 문장별 주어·목적어·보어에서 주장을 구성하는 핵심 명사를
   내부 목록으로 만든다. 조사·어미는 바꿔도 앵커의 원형 어휘는 결과에 최소 한 번 남긴다.
3. 룰북 순서대로 고친다: P(관용구) → T(번역투) → S(구조) → F(형식) → V(목소리 조정).
   V는 마지막이다 — 앞에서 깎은 게 있으면 여기서 되살린다.
4. 자체검증 6항을 점검하고, 위반한 편집만 롤백한다.
5. `final.md` 로 쓴다. 본문 끝에 `<!-- GYEOL-SUMMARY -->` 블록을 붙인다.

## 자체검증 6항

1. 원문에 없던 사실·이름·숫자·날짜·인용을 추가하지 않았는가
2. 내용 앵커가 전부 살아 있는가
3. 구어 어미·1인칭·유보·자기비하를 지우지 않았는가 (V-1)
4. 서법을 바꾸지 않았는가 — 당위("해야 한다")를 단정("한다")으로, 유보("일 수 있다")를
   단정으로 바꾸지 않았는가
5. 종결 체계를 섞지 않았는가 (V-3)
6. 문장 길이가 원문보다 평평해지지 않았는가 (V-2)

**3번과 6번이 이 스킬의 핵심이다.** 1·2·4번을 지키면서 3·6번을 어기는 윤문이 가장 흔한
실패다 — 의미는 보존됐는데 사람 냄새만 빠진다.

## 산출 형식

본문 뒤에:

```markdown
<!-- GYEOL-SUMMARY -->
| 항목 | 값 |
|---|---|
| 겨냥한 패턴 | P-1, T-6, S-2 |
| 손댄 문장 | 12 / 87 |
| 자체검증 | 6/6 통과 |
| 보류한 구간 | 2곳 (인용문, 확신 부족) |
```

## 금지

- 변경률을 스스로 판정하지 않는다. 그건 `verify_gates.py` 가 한다. 위 표의 숫자는 참고값이다.
- 문단을 통째로 새로 쓰지 않는다. 문장 단위로 고친다.
- "더 좋게" 만들지 않는다. 원문에 없던 통찰·비유·마무리를 넣지 않는다.
